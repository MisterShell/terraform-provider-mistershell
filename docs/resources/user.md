# mistershell_user (Resource)

Manages a MisterShell user. Role assignments are managed separately via mistershell_user_role; this resource exposes assigned roles read-only. password is required when creating a user, and may be omitted after import or to stop managing it. Only LOCAL users support password rotation. Import by integer ID.

## Example Usage

```terraform
# A local user. password is required (the API requires it for every auth type).
# Changing password rotates it via the admin reset endpoint; changing email or
# auth_type replaces the user.
resource "mistershell_user" "alice" {
  email      = "alice@example.com"
  first_name = "Alice"
  last_name  = "Anderson"
  password   = "change-me-please"
  is_active  = true
}

# An externally-authenticated user. A password is still required by the API even
# for external auth types (its complexity is not enforced for non-LOCAL users).
# Such users are normally provisioned at login, but the API permits creating
# them directly.
resource "mistershell_user" "oidc_bob" {
  email      = "bob@example.com"
  first_name = "Bob"
  last_name  = "Baker"
  auth_type  = "OIDC"
  password   = "change-me-please"
}
```

## Schema

### Required

- `email` (String) Canonical lowercase user email address (unique). Changing it forces replacement.
- `first_name` (String) User first name.
- `last_name` (String) User last name.

### Optional

- `auth_type` (String) Authentication type. One of LOCAL, LDAP, OIDC, SAML. Defaults to LOCAL. A password is required for all types; complexity rules are enforced for LOCAL only.
- `is_active` (Boolean) Whether the user account is active. Defaults to true.
- `password` (String, Sensitive) Required when creating any user. Omit after import or to stop password management. Changes rotate LOCAL passwords; external users cannot rotate passwords. Stored in state; never returned by the API.

### Read-Only

- `auth_provider_id` (Number) ID of the external authentication provider (mistershell_auth_provider) the user signs in through; null for LOCAL users and for users not yet linked to a provider. Read-only; null on MisterShell < 2.0.9.
- `created_at` (String) Creation timestamp.
- `email_verified` (Boolean) Whether the user's email is verified (read-only).
- `id` (Number) User ID.
- `permissions` (Set of String) Flattened permission names granted through assigned roles (read-only).
- `roles` (Attributes List) Roles assigned to this user, as objects with id, name, and description (read-only; manage assignments via mistershell_user_role). (see [below for nested schema](#nestedatt--roles))
- `updated_at` (String) Last update timestamp.

### `auth_type` values

| value | meaning | password |
|---|---|---|
| `LOCAL` | Password-based local account (default). | Required (complexity policy enforced) |
| `LDAP` | Account authenticated against an LDAP provider. | Required (hashed; complexity policy not enforced) |

External (`LDAP`/`OIDC`/`SAML`) users are normally provisioned automatically at
first login; creating them through this resource is supported but uncommon. A
password is still required by the API for every auth type.
