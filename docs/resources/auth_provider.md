# mistershell_auth_provider (Resource)

Manages a MisterShell external authentication provider (LDAP, OIDC, or SAML). The config attribute is a native per-provider_type Terraform object carrying secrets; the API masks secrets ('****') and enriches non-secret defaults, so config is stored from your plan (not read back). display_order is set declaratively (honored on create; omitted appends at the end). Create and update require an active license.

## Example Usage

```terraform
# An OIDC auth provider. config is a native per-provider_type Terraform object;
# client_secret is a secret (masked '****' by the API and
# stored from your configuration, not read back). mnemonic is immutable and is
# used in stable login and callback URLs.
#
# Create and update require an active license.
resource "mistershell_auth_provider" "corp_oidc" {
  name          = "corp-oidc"
  mnemonic      = "corp-oidc"
  provider_type = "OIDC"
  is_enabled    = true
  display_order = 0

  config = {
    issuer_url    = "https://login.example.com"
    client_id     = "mistershell"
    client_secret = var.oidc_client_secret # secret
    scopes        = ["openid", "profile", "email"]
  }
}

variable "oidc_client_secret" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `config` (Dynamic, Sensitive) Per-provider_type config as a native Terraform object. For LDAP: server_url, bind_dn, bind_password (secret), base_dn, and optional user_search_filter/user_attributes/group_search_base/group_search_filter/use_tls/tls_verify/connection_timeout. For OIDC: issuer_url, client_id, client_secret (secret), and optional scopes/claims_mapping/redirect_uri/additional_params/tls_verify. For SAML: idp_entity_id, idp_sso_url, idp_x509_cert (PEM, BEGIN/END CERTIFICATE markers required), and optional attribute_mapping/sign_requests/want_assertions_signed/sp_private_key (secret)/sp_x509_cert; SAML rejects unknown keys (the SP URLs are derived server-side and exposed as the read-only sp_entity_id/sp_acs_url attributes). The API masks secrets as '****' and enriches non-secret defaults, so this value is stored from config (not read back) and is not importable.
- `mnemonic` (String) Stable URL token used in login, callback, ACS, and metadata URLs. Immutable after creation.
- `name` (String) Unique provider name (1-100 characters).
- `provider_type` (String) Provider type. One of: LDAP, OIDC, SAML. Cannot be changed after creation (the config shape is type-coupled).

### Optional

- `display_order` (Number) Login-page display order (>=0). Omit to keep the server's auto-assigned value (max+1). Assign distinct values for deterministic ordering; set declaratively via PATCH (the provider never calls the reorder endpoint).
- `is_enabled` (Boolean) Whether the provider is enabled. Defaults to true.

### Read-Only

- `created_at` (String) Creation timestamp.
- `group_mappings_count` (Number) Number of external group->role mappings attached to this provider.
- `id` (Number) Auth provider ID.
- `oidc_redirect_uri` (String) OIDC callback URL to register with the identity provider. Derived from app_base_url and mnemonic; null for LDAP/SAML.
- `sp_acs_url` (String) SAML only (null for LDAP/OIDC): Assertion Consumer Service URL derived from app_base_url and mnemonic; register it with your IdP.
- `sp_entity_id` (String) SAML only (null for LDAP/OIDC): service-provider entity ID derived from app_base_url and mnemonic; register it with your IdP.
- `updated_at` (String) Last update timestamp.

## `display_order` semantics

`display_order` controls the login-page ordering of providers:

- **Omit `display_order`** to keep the server's auto-assigned value (`max + 1` on
  create). The value is read back into state (Optional + Computed), so omitting it
  does not produce a perpetual diff.
- **Assign distinct values** for a deterministic login-page order. The backend
  does **not** enforce unique `display_order`; duplicates break ties by `id`.
- **Create cannot set `display_order`** (the server auto-assigns it). When you pin
  a value, the provider applies it with a follow-up PATCH after create; thereafter
  it is set on update. The provider **never** calls the backend's reorder endpoint.

## The `config` object

`config` is a native Terraform object. Its shape is determined by `provider_type` (one table per type
below). Each type carries at least one **secret** field.

**Secret & drift handling.** Every secret field (LDAP `bind_password`, OIDC
`client_secret`, SAML `sp_private_key`) is encrypted at rest and **masked to
`****`** in the API's responses. As with `credential_data`, the provider stores
the **entire `config` from your configuration** and does **not** read it back from
the server — for **all** provider types, not just the secret fields. This is
necessary because the server also **enriches** non-secret defaults (LDAP
`user_search_filter`/`user_attributes`; OIDC `scopes`/`claims_mapping`/
`redirect_uri`; SAML `attribute_mapping`/`sign_requests`/
`want_assertions_signed`), so reflecting the server value would churn.
Consequences:

- After **importing** a provider, `config` is unknown until you re-supply it in
  HCL — secrets cannot be recovered from the masked server value. `config` is
  **excluded from import** (only `id` is set on import).
- Out-of-band changes to the **non-secret** parts of `config` are **not** detected
  as drift, because the whole `config` is preserved from state. This is the
  documented trade-off of the stored-from-config rule (identical to
  `credential_data`).

**License.** `config` create/update (and group-mapping create/update) require an
active license; an unlicensed instance returns a `403` error, surfaced verbatim.
Delete works unlicensed.

### `provider_type = "LDAP"` config

| field | type | required | default | secret |
|---|---|---|---|---|
| `server_url` | string (`ldap://` or `ldaps://`) | **yes** | — | no |
| `bind_dn` | string (DN) | **yes** | — | no |
| `bind_password` | string | **yes** | — | **yes** |
| `base_dn` | string (DN) | **yes** | — | no |
| `user_search_filter` | string (must contain `{username}`) | no | `(uid={username})` | no |
| `user_attributes` | object (string→string map, non-empty) | no | `{email = "mail", first_name = "givenName", last_name = "sn"}` | no |
| `group_search_base` | string (DN) or null | no | `null` | no |
| `group_search_filter` | string (parenthesized) | no | `(member={user_dn})` | no |
| `use_tls` | boolean | no | `true` | no |
| `tls_verify` | boolean | no | `false` | no |
| `connection_timeout` | integer (1-60) | no | `10` | no |

`use_tls` and `tls_verify` are independent: `use_tls` encrypts the connection,
`tls_verify` decides whether the LDAP server's certificate is validated (against
the system + custom CA store). Note the default is **`false`** — an encrypted but
unverified connection. Set `tls_verify = true` against a directory whose
certificate chains to a trusted CA. (This differs from OIDC, where `tls_verify`
defaults to `true`.)

Example:

```hcl
config = {
  server_url    = "ldaps://ldap.example.com:636"
  bind_dn       = "cn=svc,dc=example,dc=com"
  bind_password = var.ldap_bind_password # secret; masked by the API, stored from config
  base_dn       = "ou=people,dc=example,dc=com"
  use_tls       = true
}
```

### `provider_type = "OIDC"` config

| field | type | required | default | secret |
|---|---|---|---|---|
| `issuer_url` | string (https; http allowed for local test hosts) | **yes** | — | no |
| `client_id` | string | **yes** | — | no |
| `client_secret` | string | **yes** | — | **yes** |
| `scopes` | array of string (must include `openid`) | no | `["openid", "profile", "email"]` | no |
| `claims_mapping` | object (string→string map) | no | `{email = "email", first_name = "given_name", last_name = "family_name", groups = "groups"}` | no |
| `redirect_uri` | string (http/https) or null | no | auto-generated | no |
| `additional_params` | object (string→string map) | no | `{}` | no |
| `tls_verify` | boolean | no | `true` | no |

Example:

```hcl
config = {
  issuer_url    = "https://login.example.com"
  client_id     = "mistershell"
  client_secret = var.oidc_client_secret # secret; masked by the API, stored from config
  scopes        = ["openid", "profile", "email"]
}
```

### `provider_type = "SAML"` config

| field | type | required | default | secret |
|---|---|---|---|---|
| `idp_entity_id` | string | **yes** | — | no |
| `idp_sso_url` | string (https; http allowed for local test hosts) | **yes** | — | no |
| `idp_x509_cert` | string (PEM certificate; `BEGIN`/`END CERTIFICATE` markers required) | **yes** | — | no |
| `attribute_mapping` | object (string→string map) | no | `{email = "urn:oid:0.9.2342.19200300.100.1.3", first_name = "urn:oid:2.5.4.42", last_name = "urn:oid:2.5.4.4", groups = "memberOf"}` | no |
| `sign_requests` | boolean | no | `false` | no |
| `want_assertions_signed` | boolean | no | `true` | no |
| `sp_private_key` | string (PEM key) or null | no | `null` | **yes** |
| `sp_x509_cert` | string (PEM certificate) or null | no | `null` | no |

**SAML rejects unknown keys.** Unlike LDAP and OIDC (which ignore unrecognized
fields), the SAML config schema is strict: any key outside the table above fails
the apply with a `422` (`Extra inputs are not permitted`).

**The SP URLs are derived, not configured.** MisterShell computes the service
provider entity ID and ACS URL from the instance's `app_base_url` setting plus
the immutable provider `mnemonic`. They are exposed as the read-only `sp_entity_id` / `sp_acs_url`
attributes — register those values with your IdP:

```hcl
output "saml_acs_url" {
  value = mistershell_auth_provider.saml.sp_acs_url
}
```

They are **not** `config` fields. Earlier releases documented `config.sp_entity_id`
and `config.sp_acs_url`; those inputs have been removed and now trigger the `422`
above, so drop them from `config` when upgrading.

Example:

```hcl
config = {
  idp_entity_id  = "https://idp.example.com/metadata"
  idp_sso_url    = "https://idp.example.com/sso"
  idp_x509_cert  = file("idp.crt")
  sp_private_key = var.saml_sp_private_key # secret; masked by the API, stored from config
}
```

## Import

Import is supported using the following syntax:

```shell
# Auth providers are imported by their integer ID.
# Note: config is NOT read back from the server (the API masks secrets and
# enriches non-secret defaults); after importing, set config in your
# configuration yourself. config is excluded from import.
terraform import mistershell_auth_provider.corp_oidc 3
```
