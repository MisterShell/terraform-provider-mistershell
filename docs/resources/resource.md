# mistershell_resource (Resource)

Manages a MisterShell network resource through live RDK onboarding. Creation requires a successful connection and may take several minutes. Set engine_id for automatic discovery (SSH falls back to Generic SSH) or resource_type for exact-type discovery. external_id is discovered and may be null.

## Example Usage

```terraform
# Automatic onboarding: MisterShell connects through SSH, discovers the most
# specific installed native type, and falls back to Generic SSH when no native
# detector matches. A successful connection is required in either case.
resource "mistershell_resource" "automatic" {
  name          = "edge-router.zurich"
  engine_id     = "ssh"
  location_id   = mistershell_location.zurich.id
  credential_id = mistershell_credential.ssh_admin.id

  connector_data = {
    host = "10.0.1.1"
    port = 22
  }
}

# Exact onboarding: when resource_type is supplied, MisterShell infers the
# engine and accepts the target only if that exact detector matches.
resource "mistershell_resource" "known_ios" {
  name          = "known-ios-router.zurich"
  resource_type = "cisco_ios"
  location_id   = mistershell_location.zurich.id
  credential_id = mistershell_credential.ssh_admin.id

  connector_data = {
    host = "10.0.1.2"
    port = 22
  }
}

# Generic SSH is the exact-type special case: a successful SSH connection is
# sufficient and no native discovery is run. external_id is normally null.
resource "mistershell_resource" "generic_ssh" {
  name          = "shell-only-host.zurich"
  resource_type = "generic_ssh"
  location_id   = mistershell_location.zurich.id
  credential_id = mistershell_credential.ssh_admin.id

  connector_data = {
    host = "10.0.1.3"
    port = 22
  }
}

resource "mistershell_tag" "production" {
  name  = "production"
  color = "#e53935"
}

# tag_ids owns the complete tag set. Omit it to leave tags unmanaged; use []
# to actively keep the resource tag-free.
resource "mistershell_resource" "tagged" {
  name          = "tagged-router.zurich"
  engine_id     = "ssh"
  location_id   = mistershell_location.zurich.id
  credential_id = mistershell_credential.ssh_admin.id
  connector_data = {
    host = "10.0.1.4"
    port = 22
  }
  tag_ids = [mistershell_tag.production.id]
}
```

## Onboarding modes

Creating a resource always performs a live connection test and can take several
minutes. The provider waits up to five minutes for the worker task and its
single-use discovery proof.

- Set `engine_id` without `resource_type` for automatic onboarding. MisterShell
  tries the installed native detectors in RDK order. SSH falls back to
  `generic_ssh` after a successful connection when no native type matches;
  engines without a fallback fail when nothing matches.
- Set `resource_type` for exact onboarding. The provider resolves its engine
  from MisterShell's installed RDK catalog, and onboarding fails unless that
  exact detector matches. `generic_ssh` is special: a successful SSH connection
  is sufficient and no native discovery is needed.
- If both are set, they must describe the same installed type/engine pair.

`external_id` is discovered by MisterShell and is read-only. It may legitimately
be null, notably for `generic_ssh`, whose transport identity is its SSH host key.
The provider never accepts a caller-supplied external identifier.

## Runtime catalogs and connector data

Resource and credential types come from the RDK bundles installed on the target
MisterShell instance; extensions may add types. The provider therefore does not
embed a closed list. Use MisterShell's `GET /api/v1/resources/types` and
`GET /api/v1/credentials/types` endpoints to inspect the current type IDs,
engine IDs, connector JSON Schemas, and compatible credential types.

The API key needs permission to read both catalogs, start discovery worker
tasks, read their status and discovery proof, create/update/delete resources,
and read/reconcile tags when `tag_ids` is managed.

## Tagging

`tag_ids` is the complete tag set managed from the resource side. Omit it to
leave tags unmanaged, or set `[]` to actively clear and keep the resource free
of tags. Do not manage the same tag-resource edge simultaneously through
`mistershell_tag.resource_ids`. The computed `tags` list always reflects live
server state.
