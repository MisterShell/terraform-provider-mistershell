# mistershell_session_policy_rule (Resource)

Manages a MisterShell session-policy rule. Rules form an ordered chain evaluated by position (lower runs first). Set distinct positions for deterministic order. Empty selector sets mean "Any"; the last remaining rule cannot be deleted.

## Example Usage

```terraform
# A deny rule placed early in the chain. Lower position runs first; assign
# distinct values (e.g. 10, 20, 30) for deterministic ordering.
resource "mistershell_session_policy_rule" "deny_dangerous" {
  name     = "deny-dangerous-shell"
  position = 10
  action   = "deny"

  session_types   = ["shell"]
  resource_types  = ["linux", "generic_ssh"]
  command_acl_ids = [mistershell_session_policy_acl.dangerous_commands.id]

  notify = true
  log    = true
}

# A broad accept rule placed later (lower priority). Empty selector sets
# (resource_types, session_types, etc.) mean "Any".
resource "mistershell_session_policy_rule" "allow_rest" {
  name     = "allow-everything-else"
  position = 20
  action   = "accept"
}

# An approval gate: members of the "on-call-leads" role must approve new
# connections to production databases. Approve rules are evaluated before all
# accept/deny rules regardless of position, and cannot reference command ACLs.
resource "mistershell_session_policy_rule" "approve_prod_db" {
  name           = "approve-production-databases"
  action         = "approve"
  resource_types = ["database_postgres", "database_mysql"]
  location_ids   = [mistershell_location.production.id]

  approval = {
    approver_role_ids  = [mistershell_role.on_call_leads.id]
    expiration_seconds = 3600 # pending requests expire after 1 hour
    validity_seconds   = 1800 # an approval grants 30 minutes of access
    notify_email       = true
  }
}
```

## Actions

| `action` | Effect when the rule matches |
|---|---|
| `accept` | Allows the connection (or, with `command_acl_ids`, the listed commands). |
| `deny` | Refuses the connection (or, with `command_acl_ids`, only the listed commands). |
| `approve` | Requires a human decision before the user opens a new connection. Requires the `approval` block and an empty `command_acl_ids`. **Requires MisterShell >= 2.0.10.** |

## Approval rules

A rule with `action = "approve"` sends the connecting user an **Approval
required** prompt and waits for one member of an approver role to approve or
deny. It is evaluated **before** all `accept`/`deny` rules, regardless of
`position`: the first matching enabled `approve` rule creates the request. After
approval, the ordinary `accept`/`deny` rules still apply in order; approval never
overrides a denial, a missing permission, or the default-deny result.

The `approval` block is required with `action = "approve"` and must be omitted
for `accept` and `deny`; the provider reports either mistake at plan time.
`approve` rules cannot reference command ACLs. `session_types`,
`resource_types`, `location_ids`, `tag_ids`, and `role_ids` select which
requests need approval as usual.

| `approval` attribute | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `approver_role_ids` | set of role IDs (1–100) | **yes** | — | Roles whose members may approve or deny. Approvers must keep resource read access in the resource's location scope. |
| `expiration_seconds` | integer, 60–2592000 | no | `86400` (24 h) | How long a pending request stays open before it expires. |
| `validity_seconds` | integer, 60–2592000 | no | `3600` (1 h) | How long an approval grants access, counted from the approval time and not extended by use. |
| `notify_email` | boolean | no | `false` | Also notify approvers by email (UI notification is always on). |
| `allow_self_approval` | boolean | no | `false` | Let a requester who belongs to an approver role decide their own request. |

Changing an `approve` rule's selectors, `approval` settings, or `enabled`
cancels that rule's pending requests and revokes its existing grants. Adding,
deleting, disabling, or reordering enabled `approve` rules revokes grants of
every session `approve` rule. Changing only `name` or `comment` does not. A role referenced in `approver_role_ids` cannot be
deleted while the rule exists; when both are managed by Terraform, reference the
role (`mistershell_role.approvers.id`) so the rule is destroyed first.

## Matching and order

Empty match sets mean “any.” `session_types` accepts `shell` and `graphical`.
`resource_types` uses the live type catalog returned by
`GET /api/v1/resources/types`, so installed extensions are supported.

Rules are evaluated by ascending `position`. Omit `position` to append using the
server-assigned value, or use distinct values such as 10, 20, and 30 for stable
ordering; `approve` rules are evaluated before all other rules (see above). The
provider updates `position` directly with PATCH. `hit_count` and
`last_hit_at` are read-only runtime telemetry. MisterShell refuses to delete the
last remaining rule.

## Import

Import is supported using the following syntax:

```shell
# Session-policy rules are imported by their integer ID.
# Note: the last remaining rule cannot be deleted (the rule chain is never
# emptied); edit it instead of destroying it.
terraform import mistershell_session_policy_rule.deny_dangerous 7
```
