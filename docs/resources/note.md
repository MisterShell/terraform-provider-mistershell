# mistershell_note (Resource)

Manages a versioned Markdown note. Acquires an advisory edit lock and rechecks the version before writing. Locks belong to the API key's user: use a dedicated user and serialize writers. The backend has no atomic conditional PUT; clients ignoring locks can still race. Destroy relinquishes management and preserves the current note and all history, including adopted notes. Import scope_type:scope_id.

Requires MisterShell >= 2.1.0.

## Example Usage

```terraform
resource "mistershell_note" "example" {
  scope_type = "location"
  scope_id   = 2
  content    = "# Operations\nManaged operations instructions."
}
# Destroy relinquishes management and preserves the note and its history.
```

## Schema

### Required

- `content` (String, Sensitive) Markdown content. Sensitive but stored in Terraform state.
- `scope_id` (Number) Positive scope ID; requires notes permission and access to the scope.
- `scope_type` (String) Scope: resource or location.

### Read-Only

- `id` (String) API identity. Catalog imports use location_id:entry_id; notes use scope_type:scope_id.
- `version` (Number) Latest observed version, used for optimistic checks before writing.

## Scope and lifecycle

| `scope_type` | `scope_id` |
|---|---|
| `resource` | Network resource ID |
| `location` | Location ID |

Content is Markdown (`text/markdown`), at most 2,000,000 characters. Read requires
`app.notes.read` and read access to the scope. Writes additionally require
`app.notes.write` and write access to the scope. API keys operate as their owning
user; use a dedicated automation user and serialize applies affecting the same
note.

The resource adopts the current note when created on a scope with an existing
note. Each changed apply appends a version. Before writing, it refuses any
existing editor lock, acquires an advisory lock, and rechecks the version.
A version mismatch aborts the write so you can refresh and review the changed
content. The backend has no atomic conditional write: a client ignoring the
advisory lock, or a concurrent session using the same API user, can still race.

Destroy preserves the current note and its entire history, including notes
created by Terraform. The backend cannot delete the current version. Remove the
resource from configuration to relinquish management; use the application to
edit the remaining content. Historical-version pruning and attachments are not
managed by this resource. Sensitive note content is still stored in Terraform
state, so restrict access to the state backend.
