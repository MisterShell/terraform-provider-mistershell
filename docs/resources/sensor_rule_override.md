# mistershell_sensor_rule_override (Resource)

Stages an enable/disable override for one sensor catalog rule. The provider does not publish these changes. Operators or scheduled backend updates in auto mode can activate staged changes. Destroy stages a reset to the rule default. This resource never invokes the global apply operation.

## Example Usage

```terraform
resource "mistershell_sensor_rule_override" "rule" {
  gid    = 1
  sid    = 2024218
  action = "disable"
}

# Review and apply staged ruleset changes separately in MisterShell.
```

- `pending` (Boolean) Whether this override differs from the active ruleset snapshot.

## Staging and reset

This resource addresses a rule in the active catalog by `gid` and `sid`. It stages
a single override using the bulk endpoint with exactly one item. It does not
activate a ruleset or invoke the global apply operation. Operators can publish
staged changes separately in MisterShell. When the backend is in `auto` mode,
scheduled ruleset updates can also publish pending overrides and source changes;
this resource does not guarantee that changes remain staged until manual review.

Destroy stages a reset of this rule's override to its catalog default. It does
not restore a pre-existing override. Resetting a previously applied override may
itself remain pending until an operator or scheduled backend update publishes it.

`pending` compares the stored override with the active ruleset snapshot.
`effective_enabled` includes staged settings and is not confirmation of sensor
deployment. Only one Terraform resource should own a given `gid`/`sid` pair.

Create refuses to overwrite an existing override. Import uses `gid:sid` and
requires an existing override in the active catalog. Import explicitly adopts
ownership; subsequent destroy resets that override to the catalog default.

If a ruleset change removes the rule from the active catalog, refresh returns an
actionable diagnostic and retains Terraform state: the backend may still hold
its durable override. Restore a catalog containing that rule to refresh normally,
or explicitly reset only that resource without refreshing it:

```shell
terraform destroy -refresh=false -target=mistershell_sensor_rule_override.rule
```

The reset endpoint does not require the rule to remain in the active catalog.
This reset is still staged; it does not publish other pending changes.
