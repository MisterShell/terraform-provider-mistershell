# mistershell_file_catalog_folder (Resource)

Manages a MisterShell file_catalog_folder. Requires the corresponding read, write and delete API permissions. Destroy refuses a nonempty folder because backend deletion is recursive. This check is not atomic; serialize catalog writers. Import location_id:entry_id. Missing entries fail refresh because listing hides permission loss; reconcile access or remove confirmed-deleted objects from state manually.

Requires MisterShell >= 2.1.0.

## Example Usage

```terraform
resource "mistershell_file_catalog_folder" "example" {
  location_id = 2
  name        = "runbooks"
  parent_path = ""
}
```

## Schema

### Required

- `location_id` (Number) Location containing this entry; requires file read/write/delete scope.
- `name` (String) Entry name, without path separators.

### Optional

- `parent_path` (String) Parent catalog path. Empty means the location root. Create parent folders first.

### Read-Only

- `id` (String) API identity. Catalog imports use location_id:entry_id; notes use scope_type:scope_id.
- `metadata` (Dynamic) Entry metadata: id, location_id, path, name, kind, size, sha256, content_type, uploaded_by, created_at and updated_at.
- `path` (String) Full catalog path.

## Folder lifecycle

Create parent folders first. Reference a parent's `path` in a child's
`parent_path` so Terraform creates and destroys the hierarchy in order. Updating
name or parent path moves the entire folder subtree. Location changes replace
the folder.

The server deletes folders recursively. This resource checks that the folder
is empty and refuses to destroy it otherwise, protecting unowned files. The
check and deletion are not atomic; serialize catalog writers while destroying.
Import uses `location_id:entry_id`.

## Entry metadata

| Field | Type and meaning |
|---|---|
| `id`, `location_id` | Integer entry identity and containing location |
| `name`, `path` | Name and full relative catalog path |
| `kind` | `file` or `folder` |
| `size` | File size in bytes; null for folders |
| `sha256` | Hexadecimal SHA-256 checksum; null for folders |
| `content_type` | Recorded MIME type, or null |
| `uploaded_by` | Uploader identity, or null |
| `created_at`, `updated_at` | Server timestamps |

Requires `app.files.read` on the location. Resource management also requires
`app.files.write` and `app.files.delete` on that location. A visible ancestor
location is navigation only: it does not grant file access. When an entry is not
visible, managed resources retain state and report an error because the API
cannot distinguish deletion from lost scope. Restore permission, or confirm the
entry was deleted and use `terraform state rm` before recreating it.
