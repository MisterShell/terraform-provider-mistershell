# mistershell_ai_agent_override (Resource)

Adopts selected settings of an existing built-in AI agent. Identity remains registry-owned. Removing a setting or destroying the override restores its captured original value; config keys absent at adoption restore their effective backend defaults. Import captures current settings as its restoration baseline. Only configured fields are owned.

## Example Usage

```terraform
data "mistershell_ai_agent" "builtin" {
  name = "General Assistant"
}

resource "mistershell_ai_agent_override" "builtin" {
  agent_id = data.mistershell_ai_agent.builtin.id
  config = {
    temperature = 0.2
    max_steps   = 12
  }
}
```

## Schema

### Required

### Optional

- `config` (Dynamic) Owned runtime settings: token_budget, max_tokens, max_steps, max_execution_time_seconds, temperature, top_p, output_format. Registry identity keys are forbidden.

## Ownership and restoration

This resource adopts an existing built-in agent by integer `agent_id`. Configure
only fields you intend Terraform to own. Name, type, description, and the config
keys `capability`, `label`, and `icon` remain registry-owned.

At adoption, `original_settings` captures the current settings. Removing an owned
field or destroying the resource restores only that field to its captured value;
unmanaged fields are left unchanged. The backend merges config and has no key
delete operation. A config key absent from the snapshot is restored to its
effective backend default: counts and execution time `0`, temperature `0.7`,
`top_p` `1`, and output format `markdown`. Existing registry-specific values are
restored from the snapshot. The built-in agent is never deleted.

`model_id = 0` explicitly selects the default model. An empty `tool_ids` set allows
all tools compatible with the agent type. Removing either argument restores the
captured selection. Avoid having multiple resources manage the same agent fields.

Import captures the agent's current values as the restoration baseline. It cannot
recover settings from before the import. Optional override fields remain unmanaged
until configured in HCL. The baseline stays in Terraform state; protect that state
and retain it until restoration is complete.
