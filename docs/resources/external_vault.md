# mistershell_external_vault (Resource)

Manages an external vault connection. MisterShell resolves secrets; Terraform never fetches them. Requires the VAULT_EXTERNAL capability (Pro or Enterprise) and an upgraded Core deployment. Sensitive configuration remains in Terraform state.

External vault support is tested against MisterShell 2.0.22. Use 2.0.22 or newer
with the Pro/Enterprise `vault.external` capability and upgraded Core instances.
The API key needs `app.auth_providers.read`, `.write`, and `.delete` permissions.

## Example Usage

```terraform
resource "mistershell_external_vault" "production" {
  name              = "Production Vault"
  mnemonic          = "production-vault"
  vault_type        = "hashicorp" # Also: openbao, aws_secrets_manager, azure_key_vault
  cache_ttl_seconds = 60

  config = {
    address           = "https://vault.example.com:8200"
    auth_method       = "approle"
    approle_role_id   = var.vault_role_id
    approle_secret_id = var.vault_secret_id
    kv_mount          = "secret"
    kv_version        = 2
  }
}

resource "mistershell_credential" "servers" {
  name              = "Server automation"
  credential_type   = "username_password"
  source            = "external"
  external_vault_id = mistershell_external_vault.production.id

  external_vault_ref = {
    base = { path = "servers/{{ resource.name }}" }
    fields = {
      username = "username"
      password = "password"
    }
  }
}

variable "vault_role_id" {
  type = string
}

variable "vault_secret_id" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `config` (Dynamic, Sensitive) Native vault-type configuration object. Secret values are preserved across masked reads. Nonsecret managed keys refresh from the API. Removing a key resets its catalog default or nullable value; unsupported removal returns a diagnostic. Imported masked secrets become null; leaving them null or omitted preserves stored credentials during unrelated edits. Supply a plaintext secret to replace it. Ambient/Kubernetes authentication uses MisterShell Core's identity and environment.
- `mnemonic` (String) Immutable identifier: 2–49 lowercase letters, digits or hyphens, starting with a letter or digit.
- `name` (String) Unique vault name (1–128 characters).
- `vault_type` (String) hashicorp, openbao, aws_secrets_manager or azure_key_vault. Immutable.

### Optional

- `cache_ttl_seconds` (Number) Secret cache lifetime, 0–3600 seconds. Defaults to 60.
- `description` (String) Description (up to 255 characters).
- `is_enabled` (Boolean) Whether the vault can be used by credentials. Defaults to true.

### Read-Only

- `created_at` (String) Creation timestamp.
- `credential_count` (Number) Number of credentials referencing this vault. References prevent deletion.
- `id` (Number) External vault ID.
- `last_check_at` (String) Timestamp of the last check. Terraform does not initiate checks.
- `last_check_error` (String) Error from the last check, if any.
- `last_check_status` (String) Status of the last check.
- `updated_at` (String) Last update timestamp.

## Configuration and references

Query `GET /api/v1/external-vaults/types` for the target instance's configuration
schema, defaults, secret fields, and reference schema. Configuration is a native
Terraform object, not JSON text. MisterShell Core performs vault authentication
and secret resolution; Terraform only manages configuration and references.

| Vault type | Authentication | Credential reference |
|---|---|---|
| `hashicorp`, `openbao` | Token, AppRole, Kubernetes | `base.path`, optional integer `base.version` for KV v2; `fields` maps to JSON keys |
| `aws_secrets_manager` | Access keys or ambient | `base.secret_id`, optional `base.version_stage`; fields map to JSON keys or `$` for the whole value |
| `azure_key_vault` | Client secret or ambient | Empty `base = {}`; fields map to secret names with optional `/version` |

Ambient and Kubernetes authentication use the identity available to **MisterShell
Core**, not the Terraform runner. Only HashiCorp/OpenBao support per-user JWT
identity. Configure the public `app_base_url`/issuer, trusted JWKS, and vault role
audience `mistershell-vault:<mnemonic>` before enabling it.

## Updates, drift and secrets

The backend merges configuration updates. When a previously configured key is
removed, the provider sends its catalog default or null if the catalog permits
it. If neither reset is supported, apply fails with an actionable diagnostic;
removal must not silently retain the old value. Authentication-mode changes
also remove obsolete identity fields according to the backend contract.

API responses mask secret fields. The resource preserves configured secrets and
refreshes configured non-secret values to detect drift. Server-added defaults
are not added to the configured object. Remote secret changes cannot be detected.
Do not use `****` or blank strings as new secrets: these can mean “keep stored
value” to the API. Sensitive values still reside in Terraform state; protect it.

The mnemonic and vault type are immutable; changing either requires replacement.
A vault cannot be deleted while either audience of any credential references it.
Use Terraform references for dependency ordering. External references produce
an API conflict and must be removed by their owner before deletion.

## Import

```shell
terraform import mistershell_external_vault.production 42
```

Import hydrates readable `config` fields and represents masked secrets as null;
it never stores the API mask as a secret value. Supply the readable configuration
in HCL. An imported null secret may remain null or be omitted while updating
other fields: the provider leaves its stored value untouched. Supply a new
plaintext secret to replace it. A previously known secret retains the usual
explicit removal/reset behavior described above. Read operations never test a
connection or fetch resolved secrets.
