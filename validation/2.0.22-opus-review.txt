## Backend facts behind N1

- The backend validates before merging, so the `****` placeholder must pass validation. It does: every secret field only requires `min_length=1` (`webhook_delivery.py:45-73`).
- The merge restores the stored value by node `id` plus `action_id` (`config_secrets.py:57-69`). If no stored value exists, it raises an error instead of silently erasing (`:91-97`).
- After the update, `Reconcile` keeps the prior state's keys for already-managed objects (`reconcile.go:75-78`) and keeps the prior value when the API returns the mask (`:68-70`). So an imported null stays null, and an omitted key stays omitted. No `****` gets into state, and you get no perpetual diff.

## Untested edge cases (none actionable)

- **Duplicate or empty node IDs:** these collide in `oldByID`. The backend ignores nodes with an empty `id` when matching (`config_secrets.py:58`), so the `****` placeholder raises an error rather than losing the secret. That failure is loud, not silent.
- **Handwritten resources with built-in rows:** `role`, `session_policy_acl`, `ai_skill` and `ai_agent` have built-in rows in the backend, but they live outside `apimanaged` and outside L-b's scope. I didn't re-audit their import paths. These are older code, not regressions, and the backend rejects builtin edits and deletes loudly rather than silently.
