# MisterShell 2.0.7 compatibility review

Review date: 2026-09-11. Provider baseline: `9ff3e73` (latest published provider:
`v2.0.1`). Backend source: `57bc6482`; both the checked-in OpenAPI document and
live `/openapi.json` identify the backend as `2.0.7`.

## Findings and proposed fixes

| Finding | Impact | Resolution for 2.0.7 |
| --- | --- | --- |
| Backend role permission migrations retire names still present in older HCL. | Refresh sees migrated grants; apply tries to restore retired names and fails with HTTP 400. | Add the complete before/after mapping to CHANGELOG and the role page. Live-test current grants and rejection of all 13 retired names. |
| Session inactivity timeout maximum dropped from 480 to 240 minutes; backend clamps larger stored values. | HCL above 240 repeatedly drifts and apply fails with HTTP 422. | Correct both setting reference pages and explain the required HCL update. Live-test 240 and rejection of 241, restoring the original setting afterward. |
| Settings tables documented 19 nonexistent keys, omitted 26 current keys, and contained stale defaults. | Users can configure nonexistent keys (HTTP 404) or rely on incorrect defaults/limits. | Rebuild resource and data-source tables from all 99 backend registry entries, including constraints and secret flags. This documentation defect predates 2.0.7. |
| Permission/edition checks tightened for log destinations, group mappings, and superuser grants. | Apply/destroy can return HTTP 403 with previously sufficient roles/licenses. | Document Pro log-forwarding capability, relevant delete grants, superuser-only grants, reserved role name, and built-in role restrictions. |
| Read scope can make existing inventory appear missing (HTTP 404). | Terraform removes inaccessible objects from state and may propose recreation. | Explain that the API key must retain scope over all managed and target locations; do not bypass backend scoping. |
| SSH fingerprint replacement requires completed resource-check evidence. The provider has no `check_task_id`, `accepted_trust_fields`, or `accepted_identity` inputs. | A raw replacement pin in `connector_data` fails with HTTP 409. Onboarding rejects worker-observed fingerprint fields with HTTP 422. Ordinary edits with omitted pins continue working. | Document the supported UI/API check-and-accept workflow and omit observed pins from HCL. Keep explicit trust/identity acceptance outside this patch release; never silently accept a replacement. |
| Documentation only required backend 2.0 and described pin preservation without a version constraint. | Users could select a backend that predates the documented collection/trust behavior. | Require backend >= 2.0.7 for this release and explain verification status becoming `unknown` after connection edits. |
| `9ff3e73` makes initial collection state atomic; published 2.0.1 applied `is_enabled = false` through a follow-up PATCH. | Automatic collection could be scheduled between resource creation and the disable request. | Publish the atomic-create fix in 2.0.7, document the existing attribute accurately, and add live regression coverage. |
| Previous SSH trust lifecycle regression used a mock server that itself preserved the pin. | Passing tests alone did not establish compatibility with the changed backend. | Add live strict/non-strict SSH coverage for proof-derived pins, initial disabled collection, connector edits, stable resource IDs, rejection of unverified replacement pins, and a clean subsequent plan. |

No removed client API paths, incompatible generated enum changes, or newly required
request fields were found in the provider's existing supported surface. Additive
backend features (including resource-check acceptance and credential usage counts)
are distinguished from regressions in existing provider workflows.

Source evidence: backend `src/features/inventory/schemas.py`,
`src/features/inventory/service.py`, `src/features/inventory/verification_evidence.py`,
`src/features/connectivity/schemas.py`, `src/core/app_settings_registry.py`,
`src/core/session_limits.py`, `src/core/permissions_registry.py`, the role-permission
normalization migrations, log-destination/group-mapping API services, and
`ui/openapi.json`.

## Validation

- Baseline `go test ./... -count=1`: passed.
- `make test-live-staged` against the configured live 2.0.7 instance: 82 top-level
  acceptance tests passed; no failures. Coverage includes onboarding, inventory,
  credentials, tags, roles, users, workers, logs/settings, session policy,
  LDAP/OIDC/SAML providers and mappings, and AI CRUD/data sources.
- Staged-suite limitations: two superseded tag tests skipped; one Windows
  credential-mismatch subtest needs a dedicated reachable Windows fixture; one
  ambiguous-resource lookup subtest is covered by unit tests instead.
- New `TestAccNetworkResource_collectionAndSSHTrust`: passed both `strict_true`
  and `strict_false` against the live backend, including cleanup verification.
- New `TestAccRole_currentPermissions`: all seven replacement permission names
  round-trip successfully; all 13 retired names are rejected.
- New `TestAccSetting_sessionInactivityLimit`: Terraform applies 240 successfully,
  241 is rejected with HTTP 422, the subsequent plan is empty, and the original
  instance value is restored after reset-on-destroy verification.
- Final `go test ./... -count=1 -timeout=10m`, `go build ./...`, `go vet ./...`,
  gofmt, and `git diff --check`: passed.
- Regenerating stable enums from backend 2.0.7 produced no changes. Generated
  Registry documentation was rebuilt twice and is idempotent.
- The live tests create and remove uniquely prefixed `tfacc-` objects and use
  an isolated SSH fixture. No API keys or environment files are committed.

## Independent review

An independent Claude Opus audit identified the missing permission-migration
notes as a release blocker, in addition to the backend-version requirement. Both
were addressed along with the settings and authorization documentation findings.
No runtime Go behavior changes were required. The final release decision is
recorded in `2.0.7-opus-review.md` once complete; publication remains gated on
explicit agreement with the final candidate.
